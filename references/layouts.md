# Page layouts

Supported IDs and decisions:

| ID | Layout guidance |
|---|---|
| `cover` | One large title, one relevant image/concept, optional supplied subtitle; no dense diagram. |
| `background` | A short context statement with one source-grounded example or image. |
| `goals` | Two to four concrete outcomes; distinguish targets from achieved results. |
| `architecture` | Components, stores and interfaces; label arrows by real direction/meaning. |
| `process` | Numbered sequence; specify the complete edge list. Prefer simple paths over crossing connectors. |
| `timeline` | Ordered events; dates only if supplied; use stages without invented dates for plans. |
| `comparison` | Same dimensions on both sides; consistent units and comparable evidence. |
| `photo-story` | One dominant photo plus up to two supporting images with factual captions. |
| `quote` | One short supplied quote and attribution; drafts labelled as drafts. |
| `results` | Evidence and outcomes; do not introduce decorative statistics. |
| `screenshot` | Original screen image in a reserved slot; restrained callouts, no redrawn evidence. |
| `evaluation` | Method, sample status, observations and limitations; distinguish pending from completed evaluation. |
| `next-steps` | Prioritized actions and owners/timing only if known. |
| `closing` | One central takeaway and optional next action; no unsupported slogan added by the model. |

The compiler uses each page's explicit `layout` description. This file is guidance for authoring that description, not a template renderer. Nine-stage processes may use a snake pattern, but state numbering and direction per row explicitly and inspect every arrow. Split overly dense relationships across pages when the requested slide count allows it.
